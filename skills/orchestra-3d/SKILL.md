# Orchestra 3D

Own the job from brief to editable model, honest preview, exported mesh and documented checks. Work in the user's language. This skill is self-contained; original Orchestra is not required.

## Activation and ownership

`$orchestra-3d`, `orchestra_3d` or an explicit request activates this workflow for the current chat. Keep it active for subsequent 3D work until the user says `stop orchestra_3d` or `normal mode`; do not apply it to unrelated work or carry state into another chat. A bare invocation starts discovery and asks what object to make; it does not invent a project.

Keep intent, dimensions, assumptions, permissions, design choices, integration and final acceptance in the main agent. Make small changes inline. Default to one child only when it saves substantial reading or provides an independent geometry review; at most two independent children, no recursive delegation. Give exact paths, units, acceptance criteria, isolated output paths and a stopping condition; request evidence and a report of about 30 lines. Return material ambiguity as `NEEDS_ESCALATION`. Only one agent controls a Blender scene or GUI. Inspect available collaboration schemas and models; prefer Luna for mechanical inspection and Sol for bounded implementation if supported. Never silently escalate to Astra or change the main model. Without collaboration, execute sequentially.

If those model choices are unavailable, work inline unless another supported choice has a concrete benefit and any material cost escalation is disclosed. These are workflow limits, not guaranteed token savings.

## Built-in efficiency

Caveman/Ponytail principles are built in; neither plugin is required. Keep concise, readable replies and evidence-based child reports; say each fact once and link artifacts instead of pasting scripts/logs. Preserve exact dimensions, units, clearance convention, commands, uncertainty and unchecked items; expand when clarity or the user's request needs it. Do not impose a caveman dialect or claim unmeasured savings.

Search specific paths/objects first, load only relevant references and batch independent reads. Reuse current evidence, inspecting changed or uncertain areas again. Reuse existing models, modifiers, parameters and installed tools before new geometry, scripts or dependencies. Make the smallest complete revision; avoid speculative variants. Use a cheap geometry preview for iteration and render final/requested views; rerender unchanged geometry only for a concrete need. Changes to mating geometry must reach dependent parts, exports and affected checks. Preserve calibration and fit parameters.

Run required print checks and the smallest meaningful additional tests; stop when acceptance passes. Do not omit validation to save tokens. For a requested handoff or context limit, save project-local dimensions, assumptions, source/export paths, checks and next action; never the full chat or secrets.

## Start with evidence

Inspect supplied files and existing project instructions. Discover Blender executable/version, available shell, computer-use tools and slicer; never assume this PC's paths exist elsewhere. Prefer Blender Python for reproducible modeling, then open the saved `.blend` in Blender when GUI access is available or requested. Preserve unsaved sessions; use a separate process and versioned outputs. Read [Blender workflow](references/blender.md) before modeling/export and [print checks](references/printing.md) before declaring a result printable.

Extract purpose, overall dimensions in millimeters, mating dimensions, loads, process/material, printer build volume and desired outputs. Ask only for missing facts that affect fit or printability. Continue independent work while waiting. Unknown printer settings do not block a labeled concept, but do block printer-specific readiness claims. Never infer exact fit from a photograph without scale. Keep assumptions explicit and editable.

## Execute and verify

1. Define measurable acceptance: envelope, interfaces/clearance, part count and requested detail. Put reusable dimensions in a short project-local parameter section or file. Reuse the existing model for revisions.
2. Build the smallest complete model. Keep printable parts separate from cameras, lights and mockup props. Produce a geometry-based preview; label any AI concept image as non-geometric.
3. Save editable `.blend` and reproducible source/parameters when generated by code. Export intended parts only, with modifiers evaluated, explicit units and axis convention. Reimport the actual STL and compare bounds to intended dimensions.
4. Run `scripts/audit_stl.py` through Blender as described in the Blender reference. Review its limits; a topology pass does not establish wall thickness, absence of self-intersections, fit or slicer readiness. Correct observed failures and rerun affected checks. After two failed attempts at the same blocker, diagnose and report the unresolved cause instead of repeating unchanged actions.
5. Inspect a rendered preview and, when available, slicer layer preview with the actual printer/material profile. Fix disappearing features, unsupported islands, wrong scale or overlaps. Deliver links to files and a short report with dimensions, assumptions, checks, remaining risks and suggested orientation/supports.

Use precise completion labels: **concept only**, **mesh checked; slicer unverified**, or **slicer checked for the named profile**. Physical fit/strength remain unverified until tested. Never invent a render, export, slicer run or print result. Generating files does not authorize uploading to a printer, heating, moving hardware or starting a print; use the user's actual authorization for those actions.
